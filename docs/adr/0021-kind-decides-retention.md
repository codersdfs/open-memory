# ADR-0021: Kind decides retention; type decides shape

- **Status:** Accepted (2026-10-19) — direction B. A row now carries `kind ∈ {decision, convention, gotcha, fact, task, note}` in addition to `type ∈ {episodic, semantic, procedural, working}`.
- **Options:** infer durability from `importance` alone vs **a lexical `kind` with its own retention window** (chosen) vs an LLM classifier vs a human `--durable` flag.
- **Why `type` is not enough:** `type` answers *what shape is this* — a fact, an event, a procedure. The question that decides whether a row may be archived is a different one: *why does this deserve to survive?* A decision, a convention and a gotcha are the three things that cost real time to rediscover; losing them silently charges the next session the same cost. They are durable by contract. A task is true for a week. A note is true until someone reads it. `type` alone cannot express that: a `semantic` row is "user lives in Berlin" (durable) or "the build is red today" (not).
- **Why not importance:** importance is the caller's guess and the archive rule already keys off `importance < 0.6`; using it as *the* durability signal is how 91.9% of the live store became never-retrieved rows that the decay pass could not touch (a durable decision and a forgotten note both sat at 0.5).
- **Why lexical, not a model:** ADR-0002 and ADR-0015 already settled the principle — the write path is zero-LLM-call, local and free. `deriveKind` is an ordered regex list (decision → gotcha → convention → task → fact → `note`), bilingual because 60% of this store is Chinese and an English-only classifier would label every Chinese decision a `note` and archive it. An explicit kind always wins, because a caller that says "record a decision" knows better than a regex.
- **Windows:** `decision`/`convention`/`gotcha` are `null` (durable, never archived by decay); `fact` 90 days, `note` 30, `task` 7. `archiveStale` returns early for durable kinds — they can only be removed by supersede or an explicit forget, never by the passage of time. The `importance < 0.6` floor still applies to the kinds that are allowed to expire, so a high-importance note is not archived either.
- **A named kind prices itself:** `KIND_IMPORTANCE` (decision 0.8, convention/gotcha 0.75, fact 0.6, task 0.5, note 0.4) and `KIND_TYPE` (convention → procedural, task → working, decision → semantic, …) apply only when the caller gave a kind and no number. An explicit `importance` always wins.

## Consequences

- `memories.kind TEXT NOT NULL DEFAULT 'note' CHECK(...)`; the migration backfills existing rows once through `deriveKind` (one batched transaction, 200k rows at a time), so an old store gets plausible kinds instead of all-`note`.
- The brief and `memory_stats` order by kind; `KIND_LABELS` renders `task` as `open` in human-facing text.
- The derivation is lexical and therefore wrong sometimes, in one direction on purpose: a sentence that *sounds* like advice ("should") becomes a convention and is over-preserved, while a decision phrased passively becomes a `note` and expires in 30 days. Over-preserving a wrong convention costs tokens in a brief; under-preserving a real decision costs the relearning. The error is biased toward the cheaper failure.
- `tests/project-memory.test.ts` pins the both-language rules, the durable windows and the decay behaviour.
