# ADR-0007: A React console beside the zero-dependency UI

- **Status:** Accepted (ticket 013, 2026-10-11)
- **Options:** build the console as more plain files in `src/ui/` vs **a separate Vite + React app in `ui/`, served at `/app`** (chosen).
- **Context:** Earlier tickets name "new dependency, framework, build step" as *not doing* (ticket 012) and `package.json` ships `"dependencies": {}`. The console asks for four views — recall-with-explain, memories + governance, a session timeline, stats — over a store whose state is a list, a score decomposition, a supersede chain and a set of histograms. The inspector does this with string-concatenated HTML into `innerHTML`, and that is exactly why the explain payload it already receives is thrown away.
- **Decision:** `ui/` is a tracked Vite + React + TS app with its **own `package.json`**. The zero-dependency promise is about the *published* `ai-memory` package — the CLI, the library and the MCP server — and a browser bundle is not a runtime dependency of any of them. Root `dependencies` stays empty; `npm test` and `npm run build` never need `ui/node_modules`.
- **Serving:** `/app/*` from `dist/src/ui-next` (built) with a dev fallback to `ui/dist`; `copy-ui.mjs` copies it best-effort so a package build on a machine that never installed the UI dev deps still succeeds. Inspector keeps `/` and `/graph.html` until a follow-up ticket swaps the root.
- **Boundary of the exemption:** no runtime dep is added to the published package, no framework enters `src/`, and deleting `ui/`, the `/app` route and one `copy-ui` block returns the repo to exactly its prior state. If a second app like this is ever proposed, that is a signal the zero-dep constraint has actually been abandoned rather than bounded — revisit here first.
- **Cost if wrong:** the repo now carries a Node-ecosystem build toolchain for one HTML surface, and `npm ci` at the root no longer describes everything needed to run the project end to end (README says so in the UI section).
