# ADR-0043: The console gets an agent, and the console gets a face

- **Status:** Accepted (2026-11-07) — the console was six query forms; the user asked for "a memory agent in the UI, and a UI worth looking at". Both halves landed together because the agent is the view that proves the design.
- **Options for the agent's brain:** client-side deterministic commands only vs **a server-side LLM tool loop with a deterministic local fallback** (chosen) vs client-side LLM (rejected: the key would sit in the browser).
- **Why the loop lives on the daemon:** the key stays in `settings.json`/env where the extractor's already reads it (`OPENAI_API_KEY`, `OPENAI_BASE_URL`, `EXTRACTOR_MODEL` — all existing settings seams, so the console can configure it and a self-hosted endpoint needs no code change); and the tools execute against the daemon's own `MemoryService`, which means a remembered fact walks the exact same gauntlet as one typed into the CLI — curation (ADR-0040), the write gate (ADR-0041), write-time reconcile (ADR-0011). The agent cannot become a second, weaker write path, because there is only one write path. A curation refusal comes back as the verdict itself, and the model is told to relay it, not apologise for it.
- **Why a fallback at all:** the same fail-open bargain as every judgment seam — a store whose chat dies because no key is configured is worse than one that answers without a model. Without a key, `POST /agent/chat` answers `501 {error:"no-model"}` and the console drops to a deterministic engine: `记住 X` → create, `概要` → brief, `统计` → stats, anything else → the agent-floor search. Every block the local mode renders is a wire answer; it invents nothing, which is the console's D4 rule applied to prose.
- **The trace is the interface, again.** D4 (the explain payload is the interface) extended to conversation: each agent turn carries `trace: [{tool, args, summary}]` rendered as a step list — what ran, what it returned, numbers included. A chat that claims things without showing the tool calls that produced them would be the one surface in the product where a score appears from nowhere.
- **Loop bounds:** ≤ 8 model steps, 60 s timeout, tool results clipped to 4 kB, incoming history ≤ 24 messages of ≤ 8 kB. The budget is a hard clip, not a hint — a runaway loop is a daemon resource, and the daemon is local.
- **Fail-open cuts both ways:** no key → 501 (never a fake reply); key present but the endpoint errors → `502 {error}` and the console offers the local mode beside the failure. The loop never writes anything the tools did not carry through the gates.
- **The design system half:** the console moves to a monochrome, flat, engineering visual system (the user picked "Codex") — ink-accent tokens (`--accent` *is* `--fg`; a filled control is inverted surface, never a hue), hairline borders, one type scale, four muted type hues reserved exclusively for memory-type dots and legends. Zero new dependencies: icons stay hand-drawn 16 px SVG (D2), motion stays SMIL/WAAPI (no CSS keyframes, no `<style>` blocks), fonts stay system stacks so the console still renders offline. Legacy token names and class names survive their restyle, so the views the redesign did not touch re-skin through tokens alone.
- **Recall and Memories re-presentation:** Recall becomes a search-first page with floor-presets as pills and ADR-0037's `diagnostics.nearMisses` folded under a "below floor · show" ghost — the honest empty state. Memories groups the page by `project` (ADR-0042's derived dimension, `null` = ungrouped last), headers carry page-count and kind chips labelled as page counts, rows click into the same drawer as before. The DataTable's j/k walk is retired on that view: a cursor model and grouping did not mix.

## Consequences

- `src/api/agent.ts` owns the loop; routes `GET /agent/status`, `POST /agent/chat` sit behind the same tier-A Origin gate as every mutation. `buildServer` takes `agentEnv` so tests inject the seam — no test talks to the network.
- `tests/agent.test.ts` covers: status without key, 501 chat without key, 400 on a body without messages, the full tool loop over a local mock completions server (row lands with `source: "agent-chat"`), and a curation refusal relayed as a verdict.
- Console additions: `Agent` view (thread persisted to localStorage per namespace, capped), `lib/agent.ts` (intent engine + LLM dispatch), `api.ts` gains `projects`/`brief`/`agentStatus`/`agentChat` and `Memory.project`/`kind` + `SearchResult.diagnostics` with wire citations.
- The console still builds offline and zero-dep; `ui:build` output is served at `/` unchanged.
- Known trade: without a model the local commands understand prefixes, not free-form intent — the composer's pill names which mode answered, so the user is never left guessing who replied.
