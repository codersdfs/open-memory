# ADR-0010: The console may write credentials, into settings.json only

- **Status:** Accepted (2026-10-17). Supersedes the "API keys stay in the environment" clause of ADR-0009; ADR-0009's restart rule, its one-process-one-vector-space boundary and its migration order all stand, extended below to say which keys a restart applies to.
- **Options:** (a) **`settings.json` grows a second whitelist of credentials, written by the console, merged by the same one env seam** (chosen); (b) keep credentials environment-only and have the console only *report* which variable a provider needs present, by name — ADR-0009's rule; (c) store credentials in an OS keyring behind a native dependency; (d) the console writes the user's `.env` directly.
- **Context:** Hand-editing `.env` was the only way to set a provider key, and two facts made that worse than it sounds. `.env` is loaded by exactly one call, `process.loadEnvFile()` in `src/config.ts:2` — so a shell export reaches the CLI and not the daemon, the daemon and not the CLI, and neither reaches a hook that runs in a client's process. And the one writable, validated, atomic seam the project already had, `settings.json`, refused credentials on purpose: `writeSettings` rejected anything key-shaped (`/API_KEY|_KEY|TOKEN|SECRET/`), which meant the file existed, was already read at two construction sites, and could not hold the values users most need to change. The store's own vocabulary is the environment's, so the fix could not be a new mapping layer: a setting key *is* an env var name (`src/core/settings.ts:20`). What ADR-0009 was protecting is still true — keys were kept out because the console was a `node:http` surface with no auth and a browser page can reach a loopback listener — but "the console may write the embedding switch" and "the console may write the key that switch needs" are the same act, and separating them left the user with a migration that could be started and not finished.
- **Decision:** `settings.json` stays flat and grows a second whitelist. `SETTING_KEYS` (`src/core/settings.ts:20`) keeps the nine embedding knobs and gains `JEV_ENDPOINT`, `JEV_MODEL`, `MEMORY_JEV`, `MEMORY_JEV_MIN`, `ENABLE_EXTRACTOR`, `EXTRACTOR_MODEL`; `SECRET_KEYS` (`:43`) is `OPENAI_API_KEY`, `NVIDIA_API_KEY`, `NIM_API_KEY`, `JEV_API_KEY`; `WRITABLE_KEYS` is their union and `writeSettings` (`:118`) accepts exactly that and refuses anything else by name — a closed list, not a pattern, because a pattern only guessed which names were credentials and a console has to name exactly which. Precedence is unchanged and never re-ordered: **real environment > `settings.json` > built-in default**, with the empty string reading as absent on both sides (`mergeEnv`, `:303`). `runtimeEnv` (`:282`, formerly `embedEnv`) is the single merge seam: `MemoryService` and the CLI build the embedder from it (`src/core/memoryService.ts:31`, `src/cli/index.ts:231`), and the judge and the extractor read it **per call** (`src/core/judgment/judge.ts:27,44,55,113,195`, `src/core/extraction/extractor.ts:42`) — which is what makes a saved key or knob live without a restart. Reads are masked: `GET /settings` reports each entry with its source (`env`/`file`/`default`/`absent`), its effect and `…` plus the last four characters (`maskSecret`, `:314`; short values get the ellipsis alone), and no key value ever appears in a response or an error body in clear. The file is written tmp-then-rename with a stale `settings.json.tmp` removed first, so an interrupted write leaves the previous file intact (`writeSettings`, `:118`), and it is created `0600` — a POSIX mode, and **on Windows `mode` is largely inert; the protection there is the user's profile ACL**, which is why no doc promises a locked file on any platform. `.env` is only ever **commented, never deleted or reordered** (`src/core/envFile.ts:136`): adopt copies the whitelisted values into `settings.json` **first**, comments the `.env` lines second, takes `.env.bak` once with flag `wx` so the first pre-edit copy survives every later adopt, and rewrites in latin1 so the bytes round-trip. A line whose value `.env` cannot be read back exactly — a backslash the loader would expand, or raw text that does not reconstruct the value — is not moved at all and is reported in `notAdopted`, because commenting it out would make a wrong `settings.json` the only copy. Names outside both whitelists (`TYPESAFE_API_KEY`, `JEV_API_KEY_FILE`) are never moved and never written; they are still *reported* by the inventory, marked not writable, so an empty console field cannot read as "no key anywhere" while a live one sits in the environment. Adopt writes settings before touching `.env` so a failure between the two leaves the value in both places, which the next call finishes — the reverse order loses it.
- **Effect timing, which is the part that generates support questions:** every credential, plus `MEMORY_JEV`, `MEMORY_JEV_MIN`, `JEV_ENDPOINT`, `JEV_MODEL`, `ENABLE_EXTRACTOR` and `EXTRACTOR_MODEL`, is **immediate** — read through `runtimeEnv()` at each use. `EMBEDDING_PROVIDER`, `EMBEDDING_DIM`, `NIM_DIM`, the two `*_EMBED_MODEL`s, the two base URLs, `NIM_INPUT_TYPE` and `NIM_TRUNCATE` need a **restart**, and remain ADR-0009's rule: one process, one vector space. `keyEffect` (`:338`) is the single table both the console and `POST /settings` read, so the UI's label is not prose that can drift from the behaviour. The restart is a command a person runs — `ai-memory daemon restart` (`src/cli/daemon.ts:129`) probes `/health`, `POST /admin/shutdown`, waits (bounded) for the port to stop answering, spawns a detached replacement, and confirms the replacement answers `/health` before it says "restarted"; from a source checkout it prints the command instead, because there is no built server entry to exec. It is never automatic, and the answer is measured rather than assumed: `POST /settings` replies with `restartRequired` and `/embedding` with `needsRestart`, both comparing the live process against what the file would build, so writing the value that is already in force does not ask for anything.
- **The surface this opens, and the gate on it:** `GET /settings`, `POST /settings`, `POST /settings/adopt-env`, `POST /admin/shutdown`, beside ADR-0009's `GET`/`POST /embedding`. The console has no auth, so the gate is two-tier and both tiers are load-bearing: **tier A**, global on every `POST`/`PATCH`/`DELETE`, refuses a present `Origin` that is not strictly loopback (an IPv4 dotted quad in `127/8`, the literal host `localhost`, or `::1`) before any handler runs; **tier B**, the console's own write routes additionally require `content-type: application/json`. The split exists because the two clients differ: a browser always attaches `Origin` to a cross-origin mutation and cannot lie about it, while the CLI, the pi extension, hooks and adapters send neither an `Origin` nor always a JSON content type — so a global 415 would break real clients and stop nothing a browser can do. An absent `Origin` stays valid. `/admin/shutdown` is loopback-peer-only and answers a non-loopback caller as if the route were not there (a 403 would confirm it exists), so stopping the server requires either a local process or a page served from this machine.
- **Rejected: an OS keyring, or any other native dependency** — it would put a compiled or N-API dependency in the published `ai-memory` package, whose `"dependencies": {}` ADR-0007 declares and the whole install story rests on. A keyring would be a better answer to the file-on-disk problem and is recorded here as the **upgrade path**, not a missing feature: it is the change that would make `0600`-on-Windows moot, and it is worth taking only when the zero-dependency promise is deliberately given up, in its own ADR. Rejected also: the console rewriting `.env` (the write a user cannot recover from, aimed at the file whose whole purpose is to be readable and shareable) and, per ADR-0009, any in-place provider swap.
- **Cost if wrong:** a local secret now lives in a plain file that the console can write, and the app has one more localhost write surface. The mitigations are honest rather than complete: `0600` where the OS honours it, an inventory that never echoes a value, a gate that stops a page on another origin, and an adopt flow that leaves a byte-identical `.env.bak` behind. A local attacker who can already read the user's home directory reads this file; the alternative was the user's `.env`, which has the same exposure and no inventory.
- **Revisit if:** the package is allowed a native dependency (keyring first), the console gains real authentication (which would make tier A's origin heuristic a second line rather than the only one), or a second writable secret store appears — two stores with one precedence order is how "which value is live" stops being answerable.
